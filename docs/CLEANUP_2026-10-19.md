# Disk cleanup, 2026-10-19 (branch exp_oct, ~50 GB -> ~10 GB)

Everything deleted here is gitignored and regenerable. This file says what was removed and how to get it back. Nothing that cannot be rebuilt was deleted.

## Kept (do not delete)
`models/` (trained PARSeq models), `data/` (incl. `master_dataset.mdb`, `open_read/`), `third_party/` (parseq), `mlflow.db`, `docs/`, all `src/`,
and in `outputs/exp_oct/`: every run's `done.json`, `eval/`, logs and configs, plus `final.ckpt` and `parseq_<run>.ckpt` (identical copies; `score_iv.py` reads the second name) for the iv runs.
`outputs/exp_oct/ssl_hwd/` (real SSL-HWD crops + `labels.csv`, needed by `ssl_hwd_sample.py`) and the `marks*`, `replay_words` folders were also kept.

## Removed, and how to restore

### 1. Virtual environments (~9 GB removed: `venv_logohtr`, `chandra_cli/.venv`; `freeze_logohtr.txt` dropped with LoGo-HTR). Pinned package lists are saved in `docs/env/`
All four were Python 3.12.9. Create with `python -m venv <dir>`, install CUDA torch first (the default Windows wheel is CPU-only), then the freeze file with `--no-deps` if pip complains.

| Dir | Purpose | Restore |
|---|---|---|
| `.venv` (KEPT) | main env (data prep, noise classifier, reports) | `pip install -r requirements.txt` (exact versions: `docs/env/freeze_main.txt`) |
| `venv_parseq` (KEPT) | PARSeq training/eval and nearly all `src/exp_oct` scripts | `pip install torch==2.11.0 torchvision==0.26.0 --index-url https://download.pytorch.org/whl/cu128`, then `pip install -r requirements-parseq.txt` (exact: `docs/env/freeze_parseq.txt`). Details: `docs/PARSEQ_REPLICATION.md` |
| `venv_logohtr` | LoGo-HTR: removed for good, see section 5 | - |
| `chandra_cli/.venv` | Chandra bounding-box inspector | follow `chandra_cli/README.md` Setup (exact: `docs/env/freeze_chandra.txt`) |

The `*_freeze` files may contain a `torch==...+cu128` local version; install torch from the cu128 index first so it resolves.

### 2. Chandra weights `chandra_cli/model_local` (9.9 GB)
Model `datalab-to/chandra-ocr-2` (HF snapshot `af93b47dba1b47b6640c86ccf487ed2260ab9a09`). `run_chandra.py` loads `chandra_cli/model_local` if present, otherwise downloads into `chandra_cli/hf_cache` on first run.
`reshard.py` was used to re-shard the single `model.safetensors` into `model_local`. Restore: just run `run_chandra.py` once (it downloads), then `python chandra_cli/reshard.py`.
`chandra_cli/out/` (0.13 GB of overlays) was kept.

### 3. Experiment LMDB training sets `outputs/exp_oct/data/` (15 GB)
All deterministic, seeded builders in `src/exp_oct/`. Run with `venv_parseq/Scripts/python <script>` from the repo root, in this order:

```
python src/master/dataset_io.py unpack            # data/master_dataset.mdb -> data/master_lmdb
# copy data/master_lmdb to outputs/exp_oct/data/master_lmdb (run_queue.py's DEFAULT_LMDB)
python src/exp_oct/build_replay.py                # replay_p10, replay_p20, replay_p30 (needs data/open_read/word_eval.csv)
python src/exp_oct/build_marks.py                 # replay30_marks6k (needs replay_p30)
python src/exp_oct/build_marks2.py                # replay30_marks2  (needs replay_p30)
python src/exp_oct/ssl_hwd_sample.py              # replay30_ssl3k   (needs replay_p30 + outputs/exp_oct/ssl_hwd/labels.csv; re-downloads crops only if missing)
python src/exp_oct/build_replay_iv.py             # iv_base, iv_replay30 (reads data/master_dataset.mdb)
```
Training: `src/exp_oct/run_queue.py` (resumable; each run writes `command.txt`, `done.json`). A finished run is skipped if `checkpoints/final.ckpt` exists, so re-running the queue is safe.
Row counts and step counts for each set are in `docs/EXPERIMENTS_OCT.md`; `build_*` print them so you can verify a rebuild.

### 4. Intermediate checkpoints (~6.5 GB)
Removed `epoch=*.ckpt` and `last.ckpt` from the six `ivbase_*` / `ivreplay30_*` runs. Their val scores are in `train.log`; the final model of each run is kept. Only needed to resume or re-pick an earlier epoch, which means retraining via `run_queue.py`.

## Rule going forward
Do not keep `epoch=*.ckpt`/`last.ckpt` after a run finishes, and delete `outputs/exp_oct/data/<set>` once its runs are done. The builders above recreate them.

### 5. LoGo-HTR removed entirely
Dropped as not needed: `third_party/LoGoHTR` and `LoGoHTR_weights`, `patches/logohtr.patch`, `src/exp_oct/logo_htr_infer.py` and `logo_htr_score.py`, `venv_logohtr`, the setup prompt doc and its pip/score logs. The zero-shot scores stay in `docs/EXPERIMENTS_OCT.md` and `outputs/exp_oct/logohtr/`.
To redo it: repo https://github.com/shreemitra/LoGoHTR (commit 9eaea5f), weights `Shree10/LoGo-HTR` on Hugging Face (`Downstream_Full_Model_Best.ckpt`, sha256 25db3a51...c432); the old scripts are in git history (commit 62690a9 and 6938c31).
